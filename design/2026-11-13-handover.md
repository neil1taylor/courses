## Your job: finish the ROVS video course

Source: `~/Projects/rovs_tutorials/docs/course/` (25 unit pages, repo `neil1taylor/rovs-tutorials`).
Scripts and the outline go in `docs/course/video/` there, never in this repo. Other sessions have

Do it the way VPC was done, which took about a day of agent time:

1. **Outline.** Write `docs/course/video/outline.json` (one entry per unit: title, outcomes, sourced
   facts, three checks). Model: `~/Projects/cohesity/course/video/outline.json`. VPC used four
   writers of six units each. Validate with `tools/video/outline.py`'s `check_outline`. Merge it,
   then run `tools/review.py rovs --approve-outline all` and commit `review/rovs.json` by PR.
2. **Modules, in batches of six.** One issue per module in rovs-tutorials. One writer agent per
   module, each given only the shared brief and its unit:
   "Follow the brief in `~/Projects/courses/design/video-briefs/writer-brief.md` exactly.
   W = <worktree>. Course folder = docs/course. Course = Red Hat OpenShift Virtualization Service.
   Your unit: <stem> (module N; check with `other`, or `first` for module 1)."
   Before you start, check two lines in the brief against the ROVS course: the company name in the
   course-ending line (BRS and VPC use Northgate), and the module 1 "tested" line (check what the
   ROVS README says was tested).
3. **Cold read.** For each batch, one Sonnet agent with
   `design/video-briefs/coldread-brief.md` and the six units. Send each writer its findings and have
   it fix them. Overrule a finding that breaks a course rule: the "If you remember one thing" line is
   required, and "in our run/lab/tests" is banned.
4. **Check, merge, look.** Run `check_script` on all six (all must print `clean`), merge the batch PR,
   then restart the review server for ROVS (`tools/review.py rovs`, in the background) and look at
   every diagram, screenshot and summary slide in Chrome at
   `http://127.0.0.1:8780/rovs/video/<stem>.html?still=<step>.<cue>`. Fix label problems by PR.
5. **Approve and voice.** `tools/review.py rovs --approve <numbers>`, copy `review/rovs.json` into a
   courses worktree, run `tools/build.py` there (it takes over 10 minutes: run it in the background),
   and commit `review/rovs.json` and `docs/` by PR.
6. **Go live** with the last batch: set `"live": True` for rovs in `VIDEO` in `tools/build.py`,
   build, check the home page links `rovs/video/`, merge. Then update this note.

## Faults the cold readers kept finding (tell writers up front; the brief covers most)

- Terms used before they are introduced in that module (a learner may start anywhere).
- A screenshot on screen while the narration talks about something the image doesn't show.
- A sentence that adds a fact or explanation the unit doesn't give.
- Two different numbers for one event, or counts that don't add up.
- A "Watch for this" tip that describes normal behaviour or a limit; it belongs in narration.
- Product-status or region wording in narration or on unit pages (remove it from unit-page prose).
- Diagrams: a box with only a title draws it centred, so an outer box hides its title behind inner
  boxes. Give it a `detail` line. Leave 24px between stacked boxes; small boxes grow to fit text.
