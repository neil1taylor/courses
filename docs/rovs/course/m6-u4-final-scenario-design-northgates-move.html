Northgate Freight is a made-up company. It runs a web, app and database application on vSphere, and it has a few physical servers. The database must survive the loss of a cluster.

The needs are made up. Every answer is a statement already made in the earlier units, with the conditions given there. Where a test measured something once, the unit says so. The review question repeats one from unit 3.2.

Step 1 · Design it

The cluster, the tier network and the disks

Three decisions about the target. Pick an answer, then read the worked answer. The drawing shows the tier layout.

Where do the workers go?

Show the worked answer

IBM recommends single-zone deployments for virtualisation workloads, because cross-zone storage replication adds latency to every VM write. Live migration is same-zone only, and VNIs and their VLAN attachments are zone-scoped. A zone spread does not survive a region loss. For production with three ODF copies, IBM's floor is six workers, not three.

The database tier must not be reachable from the web tier, and the platform must enforce it. Which design?

Show the worked answer

If tier traffic must be policed by the platform, the tier network has to be the primary network. Security groups do not see traffic inside the overlay, and traffic between VMs on one worker can bypass them. NetworkPolicy never sees a secondary interface. In the run, web to db was proven open first, then denied by policy.

Cost. One namespace per tier. OVN gives guests their addresses, and a fixed address means reserving a range. A primary network alone gave no inbound path: an edge Route returned 503 against a service proven in-cluster. This was measured on one cluster.

Which StorageClass does every Northgate VM disk use, and where do you set it for the migration?

Show the worked answer

The virtualization class is the one validated for VM disks. Choose it in the storage map, not afterwards. On the test cluster, two MTV storage maps named the generic class, the VMs sat on it, and nothing warned. Name RWX and Block yourself.

Step 2 · Design it

Getting the VMs across

Three decisions about the move itself.

Northgate has vSphere VMs and a few physical servers. Which tool for each?

Show the worked answer

MTV talks to vCenter and has no P2V path. For vSphere, MTV is documented on ROVS, was run end to end, and is free. RMM costs $110 per source VM, licence included. It needs the source powered on and SSH to every source. A ROVS target for RMM migration is documented by no public source and was observed on RMM 7.7.4.19 only. Where the ROVS target must be certain today, the chapter says MTV, or RMM to a VPC virtual server.

Northgate wants migrated VMs to keep their IP addresses, on the Layer 2 primary network. What must be true?

Show the worked answer

Preserve static IPs needs a Layer 2 primary target, the source VM powered on, and VMware Tools or open-vm-tools. A subnet mismatch means deleting and re-creating the network. If the source was off or had no agent, the VM gets a free address. Localnet and secondary networks do not preserve it, so every topology the tutorials teach otherwise means new addresses.

MTV reports every VM Running. Name one check that decides how the VM behaves from now on.

Show the worked answer

MTV hands you a running VM, not a working service. The chapter's list also has DNS, the guest agent, access rights, network policies, restarting applications and backup. Module 5 covers day two. For Regional DR, archive every MTV plan and remove its leftovers before you protect a migrated VM.

Step 3 · Design it

Protecting the order database

The goal is stated: the database must survive the loss of a cluster. Read what each answer costs before you choose.

Which copy of the data survives the loss of the whole cluster?

Show the worked answer

A VM snapshot lives on the same Ceph cluster, on the same local NVMe in the same workers. It survives a mistake, not a cluster loss. A copy outside the cluster needs object storage in a different region. One restore of a 30 GiB VM took 142 seconds, and its guest agent connected 13 seconds later. That is one run.

Northgate wants minutes of data loss, not hours, after a cluster loss. Which designs meet that?

Show the worked answer

Backup and rebuild has an RPO of hours. Regional DR's RPO is its policy interval, 5 minutes in IBM's example, and the run lost up to one interval. The chapter's choice for a few VMs that cannot wait for a restore, on ROVS with vendor-documented mechanics, is Regional DR. RackWare needs no hub and publishes no RPO. On one RHEL 9 machine a 5-minute sync schedule ran 12 cycles with no drift. Its standbys must keep running.

Cost. A second production-sized cluster, running all the time. A hub cluster. An RHACM licence, bought separately. ODF Advanced on both clusters, chosen at ordering and not changeable. The DR stack is yours to update.

What must the runbook do when the VM fails over to the DR cluster?

Show the worked answer

The network does not follow the VM. The VNI, the VLAN attachment, the CUDN and the security groups do not replicate, and the DR cluster is a different VPC with different subnets. Build the equivalent plumbing in advance, and add a step that updates whatever points at the old addresses.

Step 4 · Spot the fault

Review Northgate's draft plan

A colleague wrote the draft plan. Each line is checked against the tutorials. Does it hold?

Draft: "Map every vSphere datastore to ocs-storagecluster-ceph-rbd. It is the default class, and RWX works."

Show the answer

The generic class is not explicitly validated for VM workloads and has no mapOptions: krbd:rxbounce. Access mode does not tell the classes apart, because MTV asks for RWX and the generic class grants it. Nothing fails at migration time. Use the virtualization class.

Draft: "Put each tier on its own secondary interface and add three NetworkPolicy objects selecting the VMs. Check it with nc from web to db."

Show the answer

NetworkPolicy never saw that interface, and a refusal or a timeout on its own proves nothing. On a Layer 2 secondary network the identical denied flow succeeded with the policies in force. Prove the service reachable first, then prove it refused.

Draft: "The order database disk is cloned from the golden-image DataSource. Protect it with Regional DR."

Show the answer

A disk cloned from a DataSource is an RBD clone, and mirroring cannot be enabled on a clone until it is flattened. In the run the DRPC stayed Protected=False. A disk imported from a registry was protected within two minutes.

Draft: "Stop the Warm RackWare targets overnight to save cost. RackWare starts them at failover."

Show the answer

RackWare has no power driver for OpenShift or KubeVirt and did not start a stopped target. The failover answered No syncs were started. On ROVS, Warm and Hot are the same build, so price Warm as running. Something outside RackWare must start the machine, and that was seen on RMM 7.7.4.19.

Step 5 · Check yourself

Four questions

Is a zone spread a disaster recovery design?

Show the answer

High availability keeps VMs running when a worker fails. Disaster recovery covers a cluster, zone or region becoming unavailable. A zone spread does not survive a region loss, so it is not the second.

A VM with a VPC-routable address from a localnet subnet fails over to the DR cluster. What survives?

Show the answer

A VM that took its address from DHCP came up with no address. A VM with its own MAC and a static address, on a DR VNI holding the same address, worked.

The DR policy says 5 minutes. What does a failover lose?

Show the answer

In the run, the VM was Running on the DR cluster 81 seconds after the failover was requested, and the line written two minutes after the last sync was gone. A relocate made a final sync first and lost nothing. All the clusters in that run were in one region.

Review question from Unit 3.2. Northgate wants a different pod network range after the cluster is ordered. Can it change?

Show the answer

Neither range can change after the cluster is created. That is why Regional DR starts by planning non-overlapping addresses: the second cluster's network must not overlap the primary's.
