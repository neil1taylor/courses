Unit 1 of Module 3

The VPC under the cluster

By the end of this unit you'll be able to name the VPC pieces under a ROVS cluster, say which ones you create and which ones IBM creates, and follow the path from a subnet to a VM.

About 10 minutesNo cluster needed5 steps

Northgate Freight is a made-up haulier that's moving off vSphere. The output in this unit is real. Northgate's first ROVS cluster lives in an IBM Cloud VPC, and before they build any VM, Northgate's network admins want to know what's under it.

Every statement, error message and diagram in this unit comes from a real run on a lab cluster, apart from the review question. The VMware comparisons are rough matches of our own, and IBM doesn't describe the products this way.

Step 1 · Predict

Region, zone, prefix, subnet

A VPC spans the zones of a region. Inside one zone, an address prefix holds subnets. The drawing shows an example layout.

Northgate will have workers in two zones. Can one subnet cover both zones?

Show the answer

No. VPC subnets are zone-scoped, and there's no equivalent of a stretched Layer 2 network across zones. Plan one VM subnet in each zone that has workers.

You create a second address prefix, in a different zone, with exactly the same CIDR as an existing one. What happens?

Show the answer

It fails. A prefix must not overlap any other prefix in the same VPC, including one in a different zone. Our attempt failed with Error code: cidr_conflict -- The input cidr ... conflicts with existing vpc range ...

Step 2 · Predict

Which VPC thing is which?

These pairs are a rough match of our own, from VMware words to VPC words. IBM doesn't describe the products this way.

The VM subnet has a public gateway. Can a host on the internet start a connection to a VM on it?

Show the answer

No. A public gateway rewrites the source address of outbound traffic. Return traffic for connections the VMs start comes back in, and unsolicited inbound traffic is blocked. For inbound access you need a floating IP or a load balancer.

Spot the fault. Northgate creates a second public gateway in a zone that already has one, to serve another subnet. The create fails with Error code: over_quota ... Allocated: 1, Requested: 1, Quota: 1. What's the fix?

Show the answer

Attach the existing gateway. IBM allows one public gateway per zone in a VPC, and that gateway can be attached to as many subnets in the zone as you like.

Step 3 · Run it

Prefixes and gateways on the command line

Run each command in turn. The output is what the test VPC returned.

bash
ibmcloud is vpc-address-prefixes vpc-lab
No address prefixes were found.

This VPC was created with no prefixes at all.

By default VPC creates one for each zone, and manual prefix management turns that off.

Now describe a prefix named default-prefix. Will that work?

Show the answer

No. VPC doesn't assign a name like that. Use the real name of a prefix you created.

ibmcloud is vpc-address-prefix vpc-lab default-prefix
FAILED
Error code: not_found
Error message: Address Prefix not found
Error target name: id, type: parameter
Error target value: default-prefix

A name from a doc example isn't a name on your VPC.

ibmcloud is subnet-update vm-subnet-1 --pgw ""
FAILED
Incorrect Usage: Please pass at least one of the flags

An empty value doesn't detach the gateway.

Detaching has its own command: subnet-public-gateway-detach.

Step 4 · Follow the path

From a subnet to a VM

IBM creates two static VNIs on every worker. You create the rest of the chain: a VNI on a subnet, a VLAN attachment, and later a network on the cluster side.

The attachment says --vlan 250. The network on the cluster side says VLAN 251. What happens?

Show the answer

Nothing flows. Both sides must agree on the VLAN ID. VPC DHCP can still answer when the numbers differ, so a VM that has an address isn't proof that the path works. Test with traffic.

Spot the fault. ibmcloud ks vni attach baremetal fails with VNI Attachment and target cluster have different VPC IDs, could not attach. (E8010). What's wrong?

Show the answer

The VNI is in a different VPC. It must be in the same VPC as the cluster, and it can be on any subnet in that VPC. The zone is a separate rule, and the VNI's zone must match the worker's zone.

Step 5 · Check yourself

Three questions

Review question from Unit 1.1. Which of these can you install from OperatorHub on a ROVS cluster?

Show the answer

MTV. Only OpenShift Virtualization, NMState and Node Maintenance are blocked. Every other operator installs normally, and looking after it is your job. The add-on installs NMState for you, and the OVS bridge for VM traffic comes already built.

You create a /24 subnet. How many addresses can you give to VMs?

Show the answer

251. IBM Cloud reserves 5 addresses in every subnet, so a subnet of N addresses has N minus 5 usable. A /24 showed Address available 251 and Address total 256.

You see two VNIs on each worker that you didn't create. What do you do?

Show the answer

Leave them alone. IBM creates and attaches them with the worker. The one on eth0 carries the pod network and cluster traffic, and the one on eth1 carries the VM attachments you create. IBM says that modifying a static VNI is unsupported and can break cluster connectivity.
