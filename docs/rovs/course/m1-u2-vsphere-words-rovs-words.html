Unit 2 of Module 1

vSphere words, ROVS words

By the end of this unit you'll be able to match the vSphere words you use every day to their ROVS words, read the shape of any resource definition, and say why OpenShift works by declaring what you want.

About 10 minutesNo cluster needed5 steps

Northgate Freight is a made-up haulier that's moving off vSphere. The words and definitions in this unit are real. Northgate's admins know vSphere well, and they need the new words fast.

Every comparison in this unit is a rough match to help you find your feet. IBM doesn't describe the products this way.

Step 1 · Match the words

Nine words you already know

Each vSphere word on the left has a close ROVS word on the right. Most of the matches are close rather than exact.

A PVC is a PersistentVolumeClaim, which is a request for storage from a StorageClass. Each VM disk is backed by one. A namespace groups resources, and OpenShift calls it a project.

From vSphere: there's no single vCenter VM. The API server is the control point, and the web console gives you the GUI.

Watch for this. Host Profile has no match on ROVS. The workers are IBM's, so there's no MachineConfigPool, which is what self-managed OpenShift uses for host settings. IBM looks after the host configuration, and you reach it through ibmcloud ks worker update|replace|reload.

Step 2 · Explore the parts

Every resource has the same shape

In vSphere you click through a wizard. On OpenShift you write a definition in YAML, and that definition is the source of truth. Tap a part to see what it does, or click a line.

↑ tap any box

Type

apiVersion and kind say what you're creating, so a VM rather than a template or a network. VirtualMachine is a type that the OpenShift Virtualization operator adds, through a custom resource definition (CRD).

Name and namespace

This is the name, and the namespace the resource lives in. Every resource you create lives in a namespace.

From vSphere: it's roughly a resource pool plus a VM folder.

Watch for this. A namespace scopes names, RBAC and quotas. It doesn't isolate network traffic by default, so a pod accepts connections from any source until a NetworkPolicy selects it.

Labels

Labels are key-value pairs. A Service, a NetworkPolicy or a node selector finds its targets by label.

From vSphere: they're roughly vCenter tags and categories. In VMware, tags are mostly for organisation and reporting. In Kubernetes, labels are the main way resources are linked together.

spec

The desired state is what you want. Here it's a VM that should always be running, with a virtio boot disk, 4Gi of memory and 2 CPUs requested.

Watch for this. If you edit a running VM's spec, nothing changes live. KubeVirt sets a RestartRequired condition, and the change applies at the next restart.

status

This is the current state, which the controller writes. You read it, and you never write it.

apiVersion: kubevirt.io/v1          # API group and version
kind: VirtualMachine                 # Resource type
metadata:
  name: my-first-vm                  # Resource name
  namespace: my-vms                  # Which namespace it belongs to
  labels:                            # Key-value pairs for organisation
    app: web-server
    env: dev
spec:                                # Desired state -- what you want
  runStrategy: Always
  template:
    metadata:
      labels:
        app: web-server
    spec:
      domain:
        resources:
          requests:
            memory: 4Gi
            cpu: "2"
        devices:
          disks:
            - name: boot-disk
              disk:
                bus: virtio
      volumes:
        - name: boot-disk
          persistentVolumeClaim:
            claimName: my-vm-boot
status:                              # Current state -- set by the system
  ready: true
  printableStatus: Running
Step 3 · Predict

Which command is it?

You know the PowerCLI commands. Pick the OpenShift one that does the same job, then see the pair. oc is the general cluster tool, and virtctl does the VM-specific work.

In PowerCLI you run Get-VM. What lists every VM on the cluster?

Show the answerGet-VM, then oc get

Get-VM pairs with oc get virtualmachines -A. The -A means all namespaces. oc get nodes -o wide is the match for Get-VMHost.

You run Start-VM -VM "my-vm" today. What starts it on OpenShift?

Show the answerStart-VM, then virtctl start

virtctl start my-vm starts it. You can also set spec.runStrategy to Always, and the console has start and stop buttons.

You put an ESXi host in maintenance mode with Set-VMHost -State Maintenance. How do you do that on OpenShift?

Show the answercordon, then drain

cordon stops new workloads landing on the node, like entering maintenance mode. drain evicts what's already there, and live migrates the VMs if it can. The full form is oc adm drain <node-name> --ignore-daemonsets --delete-emptydir-data.

Step 4 · The reconciliation loop

You declare what you want, and a controller makes it happen

In vSphere each command happens once: power on, add a NIC, migrate. On OpenShift you declare the state you want, and the controllers keep working until the platform matches it.

From vSphere: the nearest idea is a vSphere HA restart policy. In Kubernetes the same pattern covers everything: network configuration, storage and security policies too.

Your VM has runStrategy: Always. You delete its virt-launcher pod. What happens?

Show the answerA new pod starts.

The controller creates a new pod. It sees that the VM should be running and isn't, and acts on the difference. The same happens if the pod crashes or the node fails.

How do you actually stop the VM and keep it stopped?

Show the answer

You change the desired state. That's the only way to keep it stopped, and you never write status yourself.

Step 5 · Check yourself

Three questions

Review question from Unit 1.1. Which of these can you install from OperatorHub on a ROVS cluster?

Show the answer

MTV. Only OpenShift Virtualization, NMState and Node Maintenance are blocked. Every other operator installs normally, and looking after it is your job.

Which vSphere idea is a namespace closest to?

Show the answer

A resource pool and a VM folder together. A namespace groups related resources, and you can apply resource limits and access controls to it. Resource quotas cap its CPU, memory and storage, like resource pool limits do. The nearest thing to a port group is a CUDN, which a later module covers.

What backs a VM disk on ROVS, in the place of a VMDK?

Show the answer

A PVC. Each VM disk is backed by one. A StorageClass is the type of storage the PVC asks for, so it's closer to a datastore.
