Storage classes and access modes

By the end you can read the request behind a VM disk, say what each ODF storage class is for, and say why a VM disk needs ReadWriteMany.

About 10 minutesNo cluster needed5 steps

Northgate Freight is a made-up company. Its admins know datastores and storage policies. Here a VM disk starts as a request, and the request carries three choices.

Every command, output and fact in this unit comes from real runs on a test cluster, recorded in tutorial chapters 35 and 102. The review question repeats one from unit 1.2.

Step 1 · Explore the parts

The request that makes a VM disk

This DataVolume names every choice, so no default decides for you. Select a part of the drawing to see what it does and which lines define it. You can also click a line.

↑ tap any box

Source

A DataVolume is how the Containerized Data Importer (CDI) gets data into a PVC. It creates the PVC with your class and size, runs an importer pod that clones the golden image into it, and marks the DataVolume Succeeded.

Watch for this. A DataVolume that leaves out the class gets the virt default, the class marked storageclass.kubevirt.io/is-default-virt-class. On ROVS that is the virtualization class, not the cluster default. Name the class anyway.

Storage class

The class decides the Ceph pool, the replication policy and the volume characteristics. ODF ships three. ocs-storagecluster-ceph-rbd-virtualization is for all VM disks. ocs-storagecluster-ceph-rbd is for container workloads, not VM disks. ocs-storagecluster-cephfs is a file class for shared filesystems for container workloads. Unit 2.2 showed why the generic class is wrong for VMs.

From vSphere: a storage class is closest to an SPBM storage policy. The virtualization class is the vSAN policy for VMs. The CephFS class is the NFS datastore.

Access mode

ReadWriteOnce (RWO) lets pods on one node mount the disk. ReadWriteMany (RWX) lets pods on several nodes mount it at once. Live migration needs RWX, because the disk must be reachable from the source and the destination node while the VM moves.

From vSphere: RWX is a VMDK on a shared datastore, which can vMotion. RWO is a VMDK on a local datastore, which cannot.

Volume mode

Block gives the VM a raw block device, with no filesystem between QEMU and the device. Filesystem mounts a directory, and QEMU writes an image file in it: one more layer. Block is the default for the virtualization class. RWX with Block is the combination that lets a VM live migrate. On Ceph RBD it is the only combination that supports multi-node access.

From vSphere: Block is like a thick eager-zeroed VMDK. Filesystem is like a VMDK on an NFS datastore.

dataVolumeTemplates:
- metadata:
    name: my-vm
  spec:
    sourceRef:
      kind: DataSource
      name: centos-stream9
      namespace: openshift-virtualization-os-images
    storage:
      storageClassName: ocs-storagecluster-ceph-rbd-virtualization
      accessModes:
      - ReadWriteMany
      volumeMode: Block
      resources:
        requests:
          storage: 30Gi
Step 2 · Predict, then run it

What if the request says nothing?

CDI keeps a storage profile for each class. It lists the combinations of access mode and volume mode that the class offers.

bash

A disk request names no access mode and no volume mode. Which combination does it get?

Show the answer

A disk that says nothing gets the first combination in the profile. Run the command to see the list.

# the storage profile of the virtualization class

oc get storageprofile ocs-storagecluster-ceph-rbd-virtualization -o jsonpath='{.status.claimPropertySets}'
[{"accessModes":["ReadWriteMany"],"volumeMode":"Block"},
 {"accessModes":["ReadWriteOnce"],"volumeMode":"Block"},
 {"accessModes":["ReadWriteOnce"],"volumeMode":"Filesystem"}]

Three combinations. RWX with Block is first, so an unnamed request gets it.

Name both modes in the DataVolume anyway, so the order of this list never decides.

Watch for this. The two RBD classes had byte-identical storage profiles on the test cluster. The access mode on a disk never tells you which class it is on.

Step 3 · Design it

Which class does Northgate pick?

Three Northgate needs. Pick a class for each, then read why.

A new Northgate VM needs a boot disk.

Show the answer

Every VM disk uses the virtualization class. It is pre-configured for virtualization and validated for start, stop, live migration and snapshots.

A Northgate container app, not a VM, needs a block volume.

Show the answer

The generic RBD class is for container workloads. It is supported but not recommended for VM disks.

A Northgate container team needs a shared filesystem that many pods mount at once.

Show the answer

CephFS is the file class, for shared filesystems for container workloads. For a VMware admin it is the closest thing to an NFS datastore.

Step 4 · Predict

One RWO disk among RWX disks

The drawing shows a VM with two disks. The boot disk is RWX with Block. Someone adds a data disk on the same class and asks for RWO.

IBM maintains the worker under this VM. Can the VM live migrate?

Show the answerEvery disk, not just the boot disk.

A single RWO data disk is enough to stop the whole VM live migrating. An RWO volume cannot be mounted on the destination node while it is still attached to the source.

The data disk is already created on the wrong class. Can you edit its PVC to fix the class?

Show the answer

Access mode and storage class cannot be changed on an existing PVC. You do not have to stop the VM to move the data: tutorial chapter 48 covers moving a running VM's disks to the right class, the Storage vMotion equivalent.

Step 5 · Check yourself

Four questions

Which access mode and volume mode do you name for a VM disk on the virtualization class?

Show the answer

RWX with Block is the combination that lets a VM live migrate. A custom class needs both settings too.

Which ODF class is closest to an NFS datastore?

Show the answer

CephFS is the file class. The virtualization class is the vSAN policy for VMs, and the generic RBD class is the default policy for non-VM workloads.

A VM has an RWX boot disk and an RWO data disk. What does the RWO disk do?

Show the answer

Every disk attached to a VM must be RWX. A single RWO data disk is enough to stop live migration.

Review from unit 1.2. What backs a VM disk on ROVS, in the place of a VMDK?

Show the answer

Each VM disk is backed by a PVC. A StorageClass is the type of storage the PVC asks for, so it is closer to a datastore.
