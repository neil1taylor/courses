Unit 2 of Module 4

Grow and add disks

By the end you can add a data disk to a VM, grow a disk while the VM runs, and say which part of the growth the platform does and which part you do inside the guest.

About 10 minutesNo cluster needed5 steps

Northgate Freight is a made-up company. Its admins resize a VMDK in vCenter without thinking. Here the disk is a PVC, and the guest still has work to do. This unit shows exactly where.

Every command, output and fact in this unit comes from real runs on a test cluster, recorded in tutorial chapter 102. The review question repeats one from unit 2.2.

Step 1 · Explore the parts

Add a data disk in two edits

A new data disk is a PVC plus two entries in the VM. Select a part of the drawing to see what it does and which lines define it. You can also click a line.

↑ tap any box

The PVC

Create the PVC first. It names the virtualization class and a size. Then oc apply -f my-vm-data-pvc.yaml makes it.

RWX and Block

Name ReadWriteMany and volumeMode: Block.

Watch for this. Every disk attached to a VM must be RWX, not just the boot disk. A single RWO data disk is enough to stop the whole VM live migrating.

The disks entry

Adds the disk on the virtio bus. The serial appears in the guest as /dev/disk/by-id/virtio-<serial>.

The volumes entry

Points the disk at the PVC by claimName. The name must match the disks entry.

Watch for this. After you apply the change, restart the VM for the new disk to appear: virtctl restart my-vm -n my-project.

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-vm-data
  namespace: my-project
spec:
  storageClassName: ocs-storagecluster-ceph-rbd-virtualization
  accessModes:
  - ReadWriteMany
  volumeMode: Block
  resources:
    requests:
      storage: 100Gi

# In spec.template.spec.domain.devices.disks:
- disk:
    bus: virtio
  name: datadisk
  serial: datadisk

# In spec.template.spec.volumes:
- persistentVolumeClaim:
    claimName: my-vm-data
  name: datadisk
Step 2 · Spot the fault

Which letter is the new disk?

Inside the VM, find the new disk by its serial, not by its letter. Run the commands. The VM here also has a cloud-init disk.

bash, inside the VM
ls -l /dev/disk/by-id/ | grep virtio
(the chapter records no output for this command)

The serial from the disks entry shows up here as virtio-datadisk.

You guess the new disk is /dev/vdb and run mkfs.xfs /dev/vdb. What happens?

Show the answer

On the test VM the cloud-init disk was /dev/vdb and the new data disk was /dev/vdc. The command stopped. With -f it would have overwritten the cloud-init disk.

sudo mkfs.xfs /dev/vdb
/dev/vdb appears to contain an existing filesystem (iso9660)

iso9660 is the cloud-init disk, not your data disk.

sudo mkfs.xfs /dev/disk/by-id/virtio-datadisk
(the chapter records no output for this command)

The serial always names the right disk. The letter depends on the other disks.

sudo mkdir /data
sudo mount /dev/disk/by-id/virtio-datadisk /data
df -h /data
(the chapter records no output for these commands; the last line of df shows the 100 GB disk mounted on /data)
Step 3 · Run it

Grow a disk while the VM runs

Ceph RBD supports online expansion, so you resize the PVC and leave the VM running. PVCs cannot be shrunk.

bash

# the recorded run asked for 35Gi; the chapter's example asks for 50Gi

oc patch pvc my-first-vm -n my-project --type merge -p '{"spec":{"resources":{"requests":{"storage":"35Gi"}}}}'
(the chapter records no output for this command)

The VM keeps running. Nothing restarts.

oc get pvc my-first-vm -n my-project
NAME          STATUS   CAPACITY   ACCESS MODES   STORAGECLASS
my-first-vm   Bound    35Gi       RWX            ocs-storagecluster-ceph-rbd-virtualization

The new capacity was reported within about 25 seconds.

Inside the guest, the disk device now reads 35G. Is the root filesystem larger too?

Show the answer

The block device grew live. The partition and the filesystem did not. Run the next command to see it.

# inside the guest

lsblk /dev/vda
vda    252:0    0   35G  0 disk
├─vda4 252:4    0 28.8G  0 part /

The disk is 35G. The root partition, vda4, is still 28.8G.

A lot of guidance says to watch for FileSystemResizePending after a resize. Will it appear on this block-mode PVC?

Show the answer

oc describe pvc showed no Conditions: section at all. That condition belongs to Filesystem-mode PVCs, where the kubelet grows a filesystem the node owns. A block PVC has no filesystem outside the guest. Judge the resize from the PVC capacity and from lsblk in the guest.

Step 4 · Predict

Four layers, two you must grow

The drawing shows what grew in step 3 and what did not.

An Ubuntu 24.04 VM has its root on /dev/vda1, formatted ext4. Which commands grow it?

Show the answerFind the partition first.

The number is not always 1. On the CentOS Stream 9 image the root is /dev/vda4 (XFS), so it takes growpart /dev/vda 4 and xfs_growfs /. Find yours with findmnt -no SOURCE,FSTYPE /. Both worked on the running VM, with no restart.

From vSphere: this is the same as editing a VM in vCenter to increase the disk size, then using diskpart (Windows) or growpart and resize2fs (Linux) inside the guest. You edit the PVC rather than the VM's hardware settings.

You run growpart on the wrong partition. What does it print?

Show the answer

On the right partition it prints CHANGED: partition=<n> ... and df -h / then shows the larger size. On the wrong one it prints NOCHANGE.

Step 5 · Check yourself

Four questions

Your colleague wants to shrink a 50Gi VM disk to 30Gi by editing the PVC. What happens?

Show the answer

The new size must be larger than the current size. PVCs cannot be shrunk.

You added a data disk and applied the VM edit. The disk is not in the guest. What is missing?

Show the answer

Restart the VM for the new disk to appear. Then find it by its serial in /dev/disk/by-id/.

After you grow a PVC, df -h / in the guest still shows the old size. Is the resize broken?

Show the answer

The block device grew live; the partition and filesystem did not. Use growpart, then xfs_growfs or resize2fs.

Review from unit 2.2. A VM's disk shows RWX. What does that tell you about its storage class?

Show the answer

Both RBD classes offer RWX Block, and the storage profile lists it first, so a request for any mode gets RWX Block on either class. Check the class name.
