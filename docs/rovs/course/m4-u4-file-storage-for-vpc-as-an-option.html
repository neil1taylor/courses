Unit 4 of Module 4

File Storage for VPC as an option

By the end of this unit you'll be able to say how File Storage for VPC differs from ODF, choose between them for a stated need, and spot the setup faults that leave its add-on Ready but unable to create a disk.

About 10 minutesNo cluster needed5 steps

Northgate Freight is a made-up haulier that's moving off vSphere. Its cluster order form asks for storage, and one of the two choices isn't ODF. This unit explains the other choice, and what to check before you rely on it.

Every command, output and fact in this unit comes from a real run on a test cluster, apart from the review question, which repeats one from unit 1.3.

Step 1 · Explore the parts

Two ways to store a VM disk

On ROVS you pick the storage option when you order the cluster, and you need at least one of ODF or File Storage for VPC. VPC Block Storage isn't deployed or used on ROVS at all.

From vSphere: ODF is closest to vSAN, and File Storage for VPC is closest to an NFS datastore. The trade-offs are the ones you already know from choosing NFS over vSAN.

Which statement about File Storage for VPC is true?

Show the answer

It's network-attached file storage in place of local NVMe. IBM says it suits non-production, development, test and lower-I/O workloads. Live migration is supported once the CDI storage profile is set up, and step 4 shows you how.

Step 2 · Design it

ODF or File Storage for Northgate?

Northgate needs four things. Pick an answer for each one, then read why.

Northgate's production VMs need the highest I/O.

Show the answer

ODF. Its performance is high because the disks are local. File Storage for VPC is moderate, because it's network storage. The catch with local disks is that IBM warns data can be unavailable when a node fails.

Northgate's development and test environment has light I/O.

Show the answer

File Storage for VPC. IBM says it's best suited to non-production, development, test and lower-I/O workloads.

Northgate needs snapshots on File Storage for VPC. IBM's pages disagree about whether they're supported. What do you do?

Show the answerA class that exists isn't the same as support.

Check your own cluster, then get the support position in writing. One IBM page says snapshots and cloning aren't supported. Another says only that support differs from ODF. On a cluster with both storage options and the right IAM role, a VM snapshot, a restore and a CDI clone all booted. For one disk the snapshot of the running VM was ready in 53 s, the restore of the stopped VM took 85 s and the clone took 202 s. Check with oc get volumesnapshotclass.

Can one cluster carry both ODF and File Storage for VPC?

Show the answer

Yes. They aren't exclusive. One test cluster had four ODF classes and seventeen File Storage classes side by side, with ocs-storagecluster-ceph-rbd-virtualization still the default virtualization class.

Step 3 · Spot the fault

The add-on says Ready, and no disk gets created

A cluster has the File Storage add-on. It reports normal and Addon Ready, and all the storage classes exist. A plain PVC with no VM stays Pending. The driver's log says this.

Error fetching iam token using trusted profile
BackendError: IAM 'get token' error, status code 400 received from
'https://private.iam.cloud.ibm.com/identity/token':
Selected trusted profile not eligible.

The cluster reports a trusted profile, set at create time. What's missing?

Show the answerEach service account needs a link to the profile.

A link for each of the two service accounts. The profile had a policy and no link, so nothing could assume it. The symptom is ibmcloud iam trusted-profile-links returning "No Trusted Profile Links found". One link for ibm-vpc-file-controller-sa and one for ibm-vpc-file-node-sa, both in kube-system, cleared the error at once with no pod restart. The add-on checks neither of them, so test with a throwaway PVC.

With the links in, the error becomes shares_access_forbidden. What do you grant?

Show the answer

Viewer on the resource group, and Editor plus Share Snapshot Operator on is. The error points at the wrong permission. With the driver's log turned up, it failed earlier, while listing subnets, with not_authorized. That set of roles let a PVC reach Bound in about 40 seconds. IAM rejects Manager, Writer and Reader for the share resource type with "Invalid role(s)". Editor on its own creates volumes but not snapshots.

Watch for this. The CSI controller caches its IAM token, so a permission change is tested against permissions from up to an hour ago. Restart the driver before you test, with oc delete pod -n kube-system -l app=ibm-vpc-file-csi-driver. A permission test that passes without a restart tells you nothing.

Step 4 · Explore the parts

Tell CDI what the storage supports

CDI doesn't recognise File Storage for VPC properties on its own. Without this step, VM disk imports fail or bind with the wrong access mode. Tap a part to see what it does. You can also click a line.

↑ tap any box

Find

The loop picks every storage profile whose provisioner is vpc.file.csi.ibm.io, so it covers every File Storage class.

Patch

This sets ReadWriteMany with Filesystem on each profile.

Watch for this. VM disks on File Storage for VPC are Filesystem rather than Block. That's the opposite of the ODF advice, and it comes from the storage itself, because network file storage can't present a raw RBD block device.

Verify

Check that each profile reports access modes that include ReadWriteMany and volumeMode: Filesystem.

for sp in $(oc get storageprofile.cdi.kubevirt.io -o json \
  | jq -r '.items[] | select(.status.provisioner == "vpc.file.csi.ibm.io") | .metadata.name'); do
  oc patch storageprofile.cdi.kubevirt.io "$sp" --type=merge \
    -p '{"spec":{"claimPropertySets":[{"accessModes":["ReadWriteMany"],"volumeMode":"Filesystem"}]}}'
done

oc get storageprofile.cdi.kubevirt.io -o yaml | grep -A4 claimPropertySets
Step 5 · Check yourself

Four questions

Which volume mode do VM disks on File Storage for VPC use?

Show the answer

Filesystem, with ReadWriteMany. Network file storage can't present a raw RBD block device.

A VM snapshot on File Storage for VPC times out. What do you check first?

Show the answer

The Share Snapshot Operator role. The first snapshot attempt on the test cluster timed out for exactly this reason. Check with ibmcloud iam trusted-profile-policies on the cluster's trusted profile. VPC also allows only one snapshot a minute for each share.

You clone the disks of a running VM on File Storage. The clone stays in SnapshotForSmartCloneInProgress. Why?

Show the answer

The source VM is running. The CDI log said CloneSourceInUse. Once we stopped the source VM, both clones finished in 215 s in the two-disk test.

Review from unit 1.3. A three-worker cluster has one worker in planned maintenance. Another worker then fails. What happens to the VMs whose data was on those copies?

Show the answerThey hang, and they don't fail over.

With one copy left, ODF's default min_size=2 blocks I/O rather than risk the data. With three workers you can survive a failure or a maintenance window, but not both at once. That isn't the behaviour a VMware admin expects, so plan for it.
