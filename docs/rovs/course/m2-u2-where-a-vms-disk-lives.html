Unit 2 of Module 2

Where a VM's disk really lives

By the end you can follow a disk write from the guest down to the drive, say which storage class every VM disk uses, and say what happens when copies of a disk are lost.

About 10 minutesNo cluster needed5 steps

Northgate Freight is a made-up company. Its admins keep asking one thing: when a VM writes to its disk, where does the data go? This unit answers it with real output.

Every command, output and fact in this unit comes from a real run on a test cluster.

Step 1 · Explore the parts

Follow one write down to the drive

A VM's disk is a volume held by ODF, the Ceph-based storage that runs on your bare metal workers. Seven things sit between an application and the drive.

From vSphere: the path is VM guest, PVSCSI driver, VMkernel, vSAN or VMFS, then the physical disk. The number of layers is similar. Ceph copies the data at the OSD, not in the VMkernel.

From vSphere: ODF is the equivalent of vSAN. A PVC, the request for a disk, is the equivalent of a VMDK file. As with vSAN, the storage and the compute fail together.

Which layer turns the guest's disk I/O into I/O against the host's block device?

Show the answer

QEMU runs in the virt-launcher pod and translates guest I/O into host-level I/O against the RBD block device. The VirtIO driver only passes the requests to QEMU.

Most Ceph guides start with a toolbox pod and the ceph command. Will that pod exist on ROVS?

Show the answer

On the cluster checked, the pod did not exist. The toolbox is created by a field on the OCSInitialization object. On ROVS that object is part of the IBM-managed storage deployment and the field was unset. Do not plan a runbook around ceph commands.

Step 3 · Spot the fault

The audit that finds nothing

An admin audits a cluster for VMs on the wrong storage class by looking for RWO disks. This is a real listing from a test cluster. Two of its lines:

$ oc get pvc -A -o custom-columns='NAME:.metadata.name,SC:.spec.storageClassName,\
AM:.spec.accessModes,MODE:.spec.volumeMode'

wave-0-pilot-web-vm-01-plan-vm-1141-5p799     ocs-storagecluster-ceph-rbd   [ReadWriteMany]   Block
wave-0-pilot-rhel9-vm-02-plan-vm-1060-vw4ww   ocs-storagecluster-ceph-rbd   [ReadWriteMany]   Block

The RWO filter returns no rows. Is the cluster clean?

Show the answerRead the class name.

Both RBD classes offer the same access modes, so a filter on access mode clears these disks. On the cluster checked, fourteen VMs sat on the generic class and every one of their disks was ReadWriteMany with Block mode. The class name is the test. The generic class lacks krbd:rxbounce, and IBM has not validated it for VM operations.

The shipped alert VMStorageClassWarning is built on a metric that counts these disks. Will it fire for a Linux VM on the generic class?

Show the answer

The alert multiplies the metric by a filter for Microsoft Windows guests, so a Linux VM on the generic class raises no alert. Query the metric kubevirt_ssp_vm_rbd_block_volume_without_rxbounce == 1 instead. On the cluster checked it returned 14 VMs, and each matched a disk the class-name query also flagged.

Watch for this. The platform gives no signal. A VM on the generic class reported LiveMigratable=True and live migrated between two workers in the test. Use ocs-storagecluster-ceph-rbd-virtualization for every VM disk.

Step 4 · Predict

What happens when copies are lost?

The pool keeps three copies and needs at least two to serve I/O. The drawing shows each case.

One worker is in maintenance and a second worker fails. How many copies of a disk are left, and what happens to a VM with data there?

Show the answerThree nodes is a lab.

One node in maintenance plus one failure leaves a single copy. Ceph blocks all I/O to the affected placement groups, and VMs with data there hang. They do not fail over. IBM's guidance for production clusters running three copies is to start with six nodes.

Keep cluster utilisation under about what figure in normal operation?

Show the answer

About 70%. ODF raises an alert at 75% on any OSD. At 95% Ceph marks the OSD full and blocks all writes. The headroom is not spare capacity: it is what recovery uses when a node goes away.

Step 5 · Check yourself

Four questions

Which storage class do you use for every VM disk?

Show the answer

The virtualization class is tuned for VM disk I/O and validated for start, stop, live migration and snapshots. The generic class is supported but not recommended for VM disks.

A VM's disk shows RWX. What does that tell you about its storage class?

Show the answer

Both RBD classes offer RWX Block, and the storage profile lists it first, so a request for any mode gets RWX Block on either class. Check the class name.

Why is a three-node cluster a lab configuration?

Show the answer

Three nodes can hold three copies. The risk is losing two at once. IBM's guidance for production clusters running three copies is to start with six nodes.

Review from unit 2.1. The VM got the address 172.17.1.200. Where does that address come from?

Show the answer

The network card is on the pod network, so the VM gets a cluster-internal address. Connecting a VM directly to a VPC subnet takes a localnet or Layer 2 network, which Module 3 covers.
