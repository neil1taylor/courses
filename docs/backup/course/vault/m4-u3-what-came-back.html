Unit 3 of Module 4

What came back and what did not

By the end you can say what the rebuild brought back whole, what came back with a gap in the first round, and what did not come back at all.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up company. Its board will ask one question: did everything come back? The honest answer has dates and numbers in it.

The second-round numbers come from one run in our lab. The first-round numbers come from one run. Each is a single run, not a promise. The vault is a Beta in us-south, with no SLA.

Terms used. Hard-linked file: a Linux file whose name points to the same data as another name. Retrieve and restore: retrieve downloads a backup from the vault to the new cluster, and restore writes its data back to a server.

Step 1 · Explore the parts

The second-round results

The lab restored each clean run to a new location and checked it against a record made before the attack. All three Succeeded.

Workload       Restored to                 Check
Linux files    /v7restore/data             sha256sum -c against the clean manifest: 503 of 503
Windows files  C:\v7restore\data           SHA-256 against the clean list: 503 match, 0 bad, 0 missing
SQL            labdb_v7b, a new database   100000,-108923937 (the clean value)

The restored database labdb_v7b read 100000,-108923937. What does that mean?

Show the answer

The clean value was 100000,-108923937. The attacked labdb still read -426859948 after the restore, so the restored database was not the attacked one.

Why did the lab restore to a new location, not to the original server?

Show the answer

In the first round the same restore to the original source was refused for a retrieved group: "Restore of a database to the original source is not allowed for remote jobs". The lab restored to new locations.

In Recoveries, each retrieved object has three snapshots. Which one do you restore?

Show the answer

The three are a metadata-only local copy, the clean vault copy and the infected vault copy. In the first round the metadata-only copy failed with "File lookup failed". The lab used the clean vault copy.

How did the lab check the Linux files?

The manifest was made before the attack. 503 of 503 matched. The next steps show why a Succeeded status is not enough.

The lab called this "pass, known gap".

Which files came back empty?

Show the answer

13,913 hard-linked files came back empty. An earlier test found the same gap, and says the cause is the file backup, not the vault.

Watch for this. The first-round times, in our lab: Linux retrieve 17 minutes and restore 38 minutes; Windows retrieve about 1 minute and restore 1 minute 22 seconds; SQL restore 1 minute 32 seconds. The second-round run did not record its times.

Step 4 · Spot the fault

"Everything came back"

Northgate's admin drafts a note for the board: "We rebuilt every workload from the vault alone, and every restore said Succeeded."

Which workload does the note leave out?

Show the answer

The retrieve of the VM group failed on a new cluster: indexing succeeded, but the snapshot failed with "Cannot find magneto view for icebox view". The VM registration on that cluster stayed Pending for 29 minutes. The second-round run did not try the VMs. The same VM backup did restore from the vault on its own cluster, in 6 minutes 6 seconds, with 20 of 20 files matching.

What found the empty Linux files?

Show the answer

In an earlier test the recovery reported Succeeded, and the checksum check found 13,902 files that differed. A status is not proof that the data is whole.

Watch for this. Say what you tested, and in which round. In the second round, Linux, Windows and SQL came back whole. In the first round, Linux had a gap and the VM did not come back.
