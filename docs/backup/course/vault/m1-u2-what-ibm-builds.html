Unit 2 of Module 1

What IBM builds: a locked bucket, two keys, an allow-list, a write window

By the end of this unit you'll be able to name the four parts of a Cyber Vault, say which key goes where, find each part on the create screens, and plan a write window that still lets you recover.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier. It backs up with Defender Data Protect, and its backup admin wants to know exactly what IBM puts in a Cyber Vault before trusting one.

The screens come from the IBM Cloud console in our lab.

Terms used. CBR: context-based restrictions, which are IBM Cloud rules that decide which networks may reach a resource. They enforce the vault's allow-list. Default retention: the number of days the vault locks every new object for; 0 means the backup software sets each lock. API: a way for programs, not people, to send requests to a service. IP range: a block of network addresses, such as those of an office network, that you can put on the allow-list. UTC: the world time standard used for every time in this course. A Z after a time also means UTC.

Step 1 · Explore the parts

One request, four parts

IBM describes the vault as a managed service. You send one create request, and you get a bucket with all four parts already in place.

When we looked at the bucket the vault had made, what did we see?

Show the answer

S3 object lock. Versioning was Enabled and object lock was Enabled with no default rule. It isn't the Immutable Object Storage retention policy.

Which of the four parts is optional?

Show the answer

The write window. Network isolation is mandatory, so you have to give at least one VPC or IP range. The daily write window is optional. IBM's overview also says that nothing can be changed after the vault is created.

Step 2 · Predict

The form fills in a number for you

Northgate's Data Protect cluster sets a lock on each object it archives. On the create form, under Object lock retention period, the field for the default retention already has a number in it when the form opens.

What should Northgate's backup admin type in the default retention field for Data Protect?

Show the answer

0. The form fills in 30 days by itself, which would lock every object for a month. The form says: "Enter 0 to apply locks manually per-object". With 0, Data Protect sets each object's lock from its archive retention, as the console steps describe.

Suppose Northgate gets the retention wrong. Can the account owner edit the vault later?

Show the answer

No. The create form says: "Once created, the vault configuration cannot be modified." IBM's overview says the same, and there's no update API. So check every setting before you click Create.

Step 4 · Spot the fault

The write window blocks reads too

Northgate's backup admin sets a write window of 02:00 to 03:00 every day. IBM's overview says: "Writes are rejected outside this window." The admin takes that to mean a recovery will work at any hour. Does it?

At 17:56 UTC, outside the window, we tried a list and a write with both keys. What happened?

Show the answer

Both were refused. The read key and the write key both got 403 for the list and the write. At 02:05, inside the window, list, write, read and check all returned 200. IBM's provisioning page matches what we saw: the window decides when the auto-created read and write policies are active.

What does that mean for Northgate's recovery plan?

Show the answer

The window has to cover the hours when Northgate might need to recover. The overview doesn't say that reads are blocked too. We found it in our lab. We didn't test whether a read identity that the customer supplies is also blocked outside the window.

Watch for this. The overview and the provisioning page disagree about reads. In our lab the provisioning page was right, so plan your window around reads as well as writes.

Step 5 · Check yourself

Three questions

Which key goes to the backup software?

Show the answer

The write key goes to the backup software. The read key is kept apart for recovery.

For a backup product that locks each object itself, what do you set the default retention to?

Show the answer

0. The form fills in 30, and says "Enter 0 to apply locks manually per-object".

A vault has a write window of 02:00 to 03:00. In our lab, what happened to a read at 17:56?

Show the answer

It was refused with 403, with both keys.

Every vault comes with a locked bucket, a write key, a read key and an allow-list. The write window is optional. Nothing can be changed after you create it. In our lab the window blocked reads as well as writes, so set it to cover the hours when you may need to recover.
