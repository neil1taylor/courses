What IBM builds: a locked bucket, two keys, an allow-list, a write window

By the end you can name the four parts of a Cyber Vault, say which key goes where, find each part on the create screens, and say what the write window also blocks.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier. It backs up with Defender Data Protect and wants to know exactly what IBM puts in a Cyber Vault before it trusts one.

The screens come from the IBM Cloud console in our lab on 10 November 2026. The test results come from 5 and 7 October 2026. The vault is a Beta in us-south, with no SLA.

Step 1 · Explore the parts

One request, four parts

IBM describes the vault as a managed service. One request makes a bucket with all of these already in place.

What did we find when we looked at the bucket the vault made?

Show the answer

Versioning was Enabled and object lock was Enabled with no default rule. It is not the Immutable Object Storage retention policy (5 October 2026).

Which of the four parts is optional?

Show the answer

Network isolation is mandatory, and at least one VPC or IP range is required. The daily write window is optional. Nothing can be changed after the vault is created (IBM's Beta overview, read 25 September 2026).

Step 2 · Predict

The form fills in a number for you

Northgate's Data Protect sets a lock on each object it archives. On the create form, the field Object lock retention period starts with a number already in it.

What should Northgate type in the default retention field for Data Protect?

Show the answer

The form fills in 30 days by itself, so every object would be locked for a month. The form says: "Enter 0 to apply locks manually per-object". With 0, Data Protect sets each object's lock from its archive retention (in the console, 10 November 2026).

Northgate gets the retention wrong. Can the owner edit the vault later?

Show the answer

The create form says: "Once created, the vault configuration cannot be modified." IBM's Beta overview agrees: there is no update API in the Beta.

Step 4 · Spot the fault

The window that blocks more than writes

Northgate sets a write window of 02:00 to 03:00 every day. IBM's overview says: "Writes are rejected outside this window." Northgate reads that as: recovery works at any hour.

At 17:56 UTC, outside the window, we tried a list and a write with both keys. What happened?

Show the answer

On 5 October 2026 both the read key and the write key got 403 for the list and the write. On 7 October at 02:05, inside the window, list, write, read and check all returned 200. IBM's provisioning page agrees with what we saw: the window decides when the auto-created read and write policies are active.

What follows for Northgate's recovery plan?

Show the answer

The overview does not say that reads are blocked too. We found it in our lab and wrote it down as a finding. Not tested: whether a read identity that the customer supplies is also outside the window.

Watch for this. The overview and the provisioning page disagree about reads. In our lab the provisioning page was right.

Step 5 · Check yourself

Three questions

Which key goes to the backup software?

Show the answer

The write key goes to the backup software. The read key is kept apart for recovery.

For a backup product that locks each object itself, what do you set the default retention to?

Show the answer

0. The form fills in 30, and says "Enter 0 to apply locks manually per-object".

A vault has a write window of 02:00 to 03:00. In our lab, what happened to a read at 17:56?

Show the answer

Refused with 403 on 5 October 2026, with both keys.
