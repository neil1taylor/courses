Unit 3 of Module 2

Defender Data Protect in ten minutes

By the end of this unit you'll be able to say what a cluster, a source, a policy and a protection group are, and where a one-node cluster runs on IBM Cloud VPC.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier. It already backs up with Defender Data Protect. Before Northgate's backup team adds a vault, it's worth being clear about the four words the console uses.

Everything here comes from the Data Protect builds and runs in our lab. The product is IBM Storage Defender 2.2.1 Data Protect, version 7.4.1.

Terms used. Agent: a small program on a server that lets the cluster back it up. KVM: a Linux feature for running virtual machines. Bare metal server: a physical server that one customer rents whole. Image: a ready-made disk file used to start a machine. Node: one machine in a cluster. OpenShift: Red Hat's platform for running software, and virtual machines, in clusters.

Step 1 · Explore the parts

Four words

The cluster is Data Protect itself, and you manage it from its own console and API. It backs up sources. A policy says when to back up and how long to keep each backup. A protection group joins what you protect to a policy.

Which one says how long a backup is kept and whether it is archived?

Show the answer

The policy. In our lab the policy was a daily backup, kept 1 day on the cluster, with every run archived to the vault for 1 day.

You click Run Now. On which of the four do you click it?

Show the answer

A protection group. In our lab we ran each of the three groups with Run Now. The dialog already carried the policy's archive line, so we didn't have to choose an archive target. On the Policies page the console counts the groups that use each policy.

In our lab, one source was a VPC virtual server with an agent and 19 GiB of test data. The cluster serves its own Linux agent, so there was no separate download.

Step 2 · Explore the parts

Where the cluster runs on IBM Cloud

IBM ships the cluster as an image for KVM. In our lab it ran as one node, inside a KVM guest, on a VPC bare metal server.

Northgate wants the cluster on IBM Cloud VPC. Where do you put it?

Show the answer

On a bare metal server. IBM ships no image for VPC virtual servers, OpenShift or OCI, and Cohesity doesn't support a cluster on VPC virtual servers.

Which software version did we install in the lab?

Show the answer

7.4.1. Only 7.3.x and 7.4.x are supported, and support for 7.2.x has ended.

Is a licence needed to run backups?

Show the answer

In our lab, none. Defender is licensed in Resource Units. We applied no licence, and the cluster still ran backups and archives. We didn't check what the console says about an unlicensed cluster.

Step 4 · Spot the fault

Two things to check in the build

Northgate's backup team follows the steps from the first build. Two things are different this time.

The first run of the install script stops at once with "Permission denied", exit code 126. Why?

Show the answer

The execute bit. In our lab the download had no execute bit, and after chmod +x on the copy it ran.

In the first build the boot disk was nvme3n1. What do you do this time?

Show the answer

Check with findmnt. The boot disk changed between builds. We checked first, then formatted the other two disks.

Watch for this. Set the cluster's host name when you create it. A cluster built without one can't back up OpenShift VMs, and the name can't be changed later.

Step 5 · Check yourself

Three questions

What joins what you protect to a policy?

Show the answer

A protection group. It has one policy, and you run the group.

Where does a Data Protect cluster run on IBM Cloud VPC?

Show the answer

On a bare metal server. Cohesity doesn't support a cluster on VPC virtual servers.

The boot disk name was different from the last build. What do you do?

Show the answer

Check it every time. In our two builds it was nvme3n1, then nvme0n1.
