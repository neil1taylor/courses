Unit 1 of Module 2

Get access: two roles and an allow list

By the end you can name what an account needs before it can create a Cyber Vault, say what a successful list call does not prove, and find the fault when a create call says the token is malformed.

About 10 minutesNo account needed4 steps

Northgate Freight is a made-up haulier. It already backs up with Defender Data Protect. Its board asks: what if an attacker gets the backup admin's keys? The answer is a Cyber Vault. First, the account needs access.

Everything here comes from runs in our lab on 25 September and 5 October 2026. The vault is a Beta in us-south, with no SLA, no warranty and no support.

Terms used. IAM role: IAM is IBM Cloud's system for deciding who may do what, and a role is a named set of permissions in it. IAM token: a short-lived string that proves who you are when you call a service. Service ID: an identity in IBM Cloud for a program, not a person. HTTP 202: the answer that means a request was accepted but is not finished. HTTP 500: the answer that means the service hit an error.

Step 1 · Explore the parts

What an account needs

The Beta is closed. IBM must put the account on an allow list. Then the user needs two roles, set by name, and a role on the storage instance.

Which role lets the user create a vault?

Show the answer

Cyber Vault Reader lists vaults. Cyber Vault Manager creates them.

Northgate's admin already has the "all IAM services" admin policy. Is that enough?

Show the answer

In our lab the "all IAM services" policy did not include the two roles. We granted them with ibmcloud iam user-policy-create on 25 September 2026 and waited about 20 seconds before the next call. The user also needs Editor or Administrator on the COS instance.

An account on Basic support cannot open the onboarding case. The notes do not record which route put our account on the list: access was missing on 25 September 2026 and present on 5 October 2026.

Step 2 · Predict

What does a good answer prove?

Northgate's admin has the Reader role. She lists the vaults with an API call. Here is what the lab saw.

When                        Result
25 Sep, before Reader role  HTTP 403, not authorized to list
25 Sep, after Reader role   HTTP 200, count 0, no vaults
5 Oct, one create           HTTP 202, then active 30 s later

The list call returns HTTP 200 with no vaults. What does that prove?

Show the answer

On 25 September 2026 the list returned 200 after the Reader role was granted. The same day, six creates failed. The list only proves the role works.

What is the only real check that an account has access?

Show the answer

On 5 October 2026 the lab made one vault with the shortest lock and no data, and deleted it at once. It was active after about 30 seconds. The delete left two keys, which were deleted by hand. The console page and IBM's email are weaker signs and were not tested as checks.

Step 3 · Spot the fault

"Token is malformed"

Northgate's admin has both roles and access. She makes a token with the CLI and calls create. The call fails.

TOK=$(ibmcloud iam oauth-tokens --output json | jq -r .iam_token)
curl -X POST .../v1/cyber_vaults -H "Authorization: Bearer $TOK" ...

HTTP 500
... token is malformed: tokenstring should not contain 'bearer ' ...

What is wrong?

Show the answer

The CLI prints the token with the word Bearer in front. Remove it with sed 's/^Bearer //' before you build the header. Our lab hit this on 25 September 2026.

The call failed. What did it leave behind?

Show the answer

A list call afterwards returned 200 with no vaults, and the instance had only the key it had before. This is different from a failed vault, which leaves keys (unit 2.2).

Watch for this. The error says "token is malformed" and comes with HTTP 500. It looks like a service fault. In our lab the cause was the extra word in our own header.

Step 4 · Check yourself

Three questions

Which role creates vaults?

Show the answer

Manager creates. Reader lists. The admin policy for all IAM services did not include either in our lab.

A list call returns HTTP 200 and no vaults. What do you know?

Show the answer

The create on 5 October 2026 was the check that showed access.

A create returns HTTP 500 and "token is malformed". What do you check first?

Show the answer

A doubled prefix gives "Bearer Bearer". The sed removes it.

Access is three things: IBM puts the account on the allow list, the user holds the Reader and Manager roles, and the user has Editor or Administrator on the COS instance. Only a create proves the allow list. Strip "Bearer " from the token before you use it.
