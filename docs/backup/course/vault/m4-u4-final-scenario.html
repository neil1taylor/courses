Unit 4 of Module 4

Final scenario: Northgate's recovery plan

By the end of this unit you'll have built a recovery plan from what the course showed, answered the directors' question about stolen keys, and worked out what stays locked after you leave.

About 20 minutesNo account needed5 steps

Northgate Freight is a made-up haulier. It backs up Linux files, Windows files and a SQL database with Defender Data Protect, and archives them to a Cyber Vault. Its directors want to know what happens if an attacker gets the backup admin's keys, and you're writing the plan.

Every number and screen in this unit comes from real runs in our lab. The unit reviews Module 4 and uses the tests from the earlier units. We ran the rebuild twice: the second test is the one in units 4.1 to 4.3, and the first test was an earlier run on a third cluster.

Step 1 · Design it

Build the recovery plan

The attack has happened and the backup cluster is gone. For each item, decide whether it goes in the plan or stays out. Your answers build the plan, and you'll see it in step 2.

Item: choose the run to download by its time, from before the attack.

Show the answer

In the plan. The infected runs were archived at 11:55, after the attack at 11:54, and in our lab the clean runs were from 11:43 and 11:44.

Item: keep a record of the clean files and the clean database values from before an attack.

Show the answer

In the plan. Every check compared the restored data with a record made earlier: a clean manifest for the files, and 100000,-108923937 for the database.

Item: replace the agent on each server with the new cluster's agent.

Show the answer

In the plan. An agent trusts one cluster. A plain rpm -Uvh --force keeps the old trust and registration fails with a TLS error, so we removed the old package and its saved configuration first.

Item: add the vault to the new cluster with the read key, Encryption off and Archive Object Lock off.

Show the answer

In the plan. Encryption is off because the archive was written without it. The lock is on the vault, and the vault enforces it, so a read-only registration doesn't need it.

Item: restore to the original server.

Show the answer

Left out. A retrieved group can't restore to the original. In our lab the restores went to /v7restore/data, C:\v7restore\data and a new database labdb_v7b.

Item: treat a restore that says Succeeded as proof.

Show the answer

Left out. In an earlier test a Linux recovery reported Succeeded while hard-linked files came back empty, and the check against a manifest is what found it.

Item: promise that the OpenShift VMs rebuild from the vault alone on a new cluster.

Show the answer

Left out. Retrieving the VM group to a new cluster failed in our first test, and the second test didn't include the VMs. On its own cluster the same VM backup did restore from the vault, so restore OpenShift VMs to the cluster they were backed up from.

Item: delete the vault when the exercise ends.

Show the answer

Left out. The vault holds locked data until the last lock ends, 15 days after the run, and it can't be deleted before then. Step 4 comes back to this.

Step 2 · Predict

The directors' question

This is the plan your answers built.

Northgate recovery plan

 3. New cluster; replace the agent on each server.

Now the directors ask what an attacker can do with stolen keys.

An attacker holds the write key. Can they delete a locked version of an archive object?

Show the answer

No. In our lab a delete of a locked version with the write key was refused with "Access Denied because object protected by object lock". It was also refused for the read key, for another key on the same storage instance, and for the account owner's token from inside the VPC.

The same attacker writes a new version of an existing object with the write key. What is left?

Show the answer

A new version, with the old one still readable. On a test object in our lab, the write returned 200 and made a new version. The first version could still be read, with its original content. The latest version was now the new content. Each write, including each backup, adds a version, and the lock keeps every earlier one.

Step 3 · Spot the fault

The draft note to the directors

Northgate's backup admin writes to the directors: "We tested the plan. Everything was recovered from the vault alone, and we can remove the vault once the test is over." Which parts of that hold up?

Is "everything was recovered" true?

Show the answer

No, it's true of the second test only. In that test, Linux (503 of 503), Windows (503 of 503) and SQL (100000 rows, checksum -108923937) were recovered exactly as they were before the attack. In the first test, Linux came back with 167,639 of 181,552 files, and retrieving the OpenShift VM to a new cluster failed.

Can Northgate remove the vault once the test is over?

Show the answer

No. The console showed one day, but the vault held data chunks locked for 9 to 15 days, with the last lock ending 15 days after the run. A vault that holds locked data can't be deleted before then.

Step 4 · What stays locked

After you leave

The test is over, and the servers and clusters can go. The vault stays, and this is what the read key showed at 11:48.

What the read key showed at 11:48
Object kind                  Count   Lock lasts
archive_metadata             3       one day
cloud_chunk_file             35      9 to 15 days
metadata/snap_tree_objects   8       9 to 15 days
configs                      -       no lock

How soon after the run can the vault be deleted?

Show the answer

15 days. That's when the newest lock ends. In the first test, the same rule held that test's vault for 18 days.

Which number tells the auditor who checks Northgate's security controls how long the data can't be deleted?

Show the answer

The lock dates in the vault. The vault enforces the lock, and in our lab the console and the policy said one day while the vault held data for up to 15.

Watch for this. A vault that holds locked data can't be deleted until the last lock ends, and the console shows a shorter lock than the vault holds. Read the dates from the vault.

Step 5 · Check yourself

Three questions

After an attack, which run do you download?

Show the answer

A run from before the attack. The newest run was made after the attack and holds the attacked data.

Why do you restore a retrieved group to a new location, not the original server?

Show the answer

Because a retrieved group can't restore to the original. In our lab the console refused it, so we restored to a new location each time.

In our lab, what was the earliest the vault could be deleted?

Show the answer

15 days. That's when the lock on the newest data ends.
