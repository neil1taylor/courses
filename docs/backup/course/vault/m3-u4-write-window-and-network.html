Unit 4 of Module 3

Write window and network isolation

By the end you can say what the vault answers to a valid key from outside its allowed network, and what a write window blocks outside its hours.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier. Its board asks what happens if an attacker gets the backup admin's keys. Can the attacker use them from the attacker's own network? And can the vault be shut outside office hours?

Every result comes from real tests in our lab on 5, 6 and 7 October 2026. The vault is a Beta in us-south, with no SLA. Hosts, IP addresses, vault names and keys are made-up or placeholders: the values were changed.

Terms used. Private IP range (RFC 1918): addresses reserved for use inside private networks, not on the internet. Vhost style and path style: two ways to write a bucket address. Vhost style puts the bucket name in the host name, and path style puts it in the path. ROVS: Red Hat OpenShift Virtualization Service on IBM Cloud.

Step 1 · Explore the parts

Two gates in front of the keys

A key is not enough. The vault also checks where the call comes from, and, if a window is set, when.

What must a vault have when it is created, about the network?

Show the answer

At least one of the allowed VPCs and the allowed IP ranges is required. IP ranges must be private (RFC 1918) (the lab's own list was its VPC and one private range).

The console form for a new vault has "Time-based write restrictions". In our console run on 10 November, what was its state by default?

Show the answer

The form showed it as Disabled, and the lab left it off. The window is optional.

Step 2 · Predict

A valid key from the wrong place

The lab vault allows only the lab VPC and its private range. On 5 and 6 October the lab sent calls with a valid key from outside. Here are the places. The answers are hidden.

What did the vault answer to the valid write key from the Mac on the public name?

Show the answer403 from outside, 200 from inside.
place                                    call                  answer
Mac on the VPN, direct and private name  list                  no answer (12 s time-out)

The Mac tests were on 5 October and the pod tests on 6 October, in our lab. The pod ran on a ROVS cluster in another VPC.

Did the Mac get in with the vhost style or the path style of the public name?

Show the answer

Both styles got 403 "Access Denied" for list, get and put.

Watch for this. One check was not run in the first round: a machine in a second VPC. The pod test on 6 October closed that gap. A valid write key from a VPC that is not on the list got nothing from the vault.

Step 3 · Run it

Inside and outside the window

A second lab vault had a write window of 02:00 to 03:00 UTC. The lab ran the same calls at 17:56 UTC on 5 October (outside) and at 02:05 UTC on 7 October (inside), from the lab VSI, inside the allowed network.

Show the answerReads were blocked too.
request                              outside      inside

The window gates reads and writes together. Inside it, the vault works as normal. One object written inside the window is locked until 8 October 2026 at 02:05:16Z.

IBM's own page was unclear whether the window blocks reads. What does the lab result say?

Show the answer

Most Beta text said reads are not windowed, but one field table said the window covers write and read. In our lab it blocked both.

Step 4 · Design it

A recovery at 14:00

Northgate sets the window 02:00 to 03:00 UTC. At 14:00 UTC a ransomware attack starts and the admin wants to read the archive.

What will the vault answer to the read key at 14:00?

Show the answer

In our lab the read key got 403 on list, get and head outside the window. A write window therefore blocks recovery outside the window too. Northgate has to weigh that when it picks the hours.

The attacker at 14:00 holds a valid write key and sits on a home network. What stops writes?

Show the answer

Every valid-key call from outside the allowed network got 403 or no answer in our lab. The window refused calls outside its hours even from inside the network.
