Unit 3 of Module 5

Private access: endpoints and context-based restrictions

By the end of this unit you'll know what an endpoint gateway gives a server, what a context-based restriction adds to IAM, and how a restriction can block a service you didn't mean to block.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier moving its vSphere estate to IBM Cloud VPC. Its backups and keys live in IBM Cloud services, and its security team wants that traffic to stay private and to be refused from anywhere else. The commands and output below are real, from a test account.

Every command and output in this unit comes from real runs in a lab account, apart from the review question.

Step 1 · Explore the parts

A private path to Object Storage, and a lock on it

An endpoint gateway gives the VPC a private address for a service. A context-based restriction then refuses requests from anywhere else. Select a part of the drawing to see what it does and which lines make it. You can also click a line.

↑ tap any box

Endpoint gateway

A gateway in your VPC that gives an IBM Cloud service a private address there. IBM describes it as horizontally scaled, redundant and spanning all zones of the VPC.

Watch for this. IBM lists these limits: one gateway per service in a VPC, and one bound IP address per zone for a gateway.

Target

The service the gateway connects to. A cloud service is named by its CRN.

Watch for this. For Key Protect, the target is an endpoint entry, not your instance's CRN. If you use the instance CRN, endpoint-gateway-create fails with Could not find service.

Security group

IBM says a gateway with no security group takes the VPC's default group. The lab makes a group that allows only HTTPS, port 443, from the app servers' group.

Watch for this. If you delete that rule, a connection to port 443 times out. If you add it back, the connection succeeds.

Reserved IPs

The gateway has one address in each of the three app subnets, and they're deleted with the gateway. The service's name now resolves to these addresses, so the server reaches the service inside the VPC.

Watch for this. A server that resolved the same name to a public address would reach the service over the public endpoint instead.

Network zone

A list of allowed locations: addresses, ranges, subnets, VPCs or services. This zone holds one VPC, vpct-prod.

Watch for this. A request through the public gateway carries the gateway's address, not the VPC's, so it doesn't match this zone.

Rule

A rule ties one or more resources to one or more zones. A rule has no name field, so the name goes in the description. Each rule here names one service instance.

Watch for this. The lab account is shared, so a rule on a whole service instead of one instance would deny other teams.

Enforcement mode

Enable denies requests that don't match and reports them. Report-only allows everything and logs what a rule would deny. Disable does nothing.

Watch for this. In the lab we created both rules in report-only mode, looked at what they would block, and only then enforced them.

ibmcloud is endpoint-gateway-create --vpc vpct-prod --name vpct-prod-cos-vpe \
  --target $COS_TARGET --target-type provider_cloud_service \
  --sg vpct-prod-vpe-sg \
  --new-reserved-ip '{"subnet":{"name":"vpct-prod-app-z1"},"name":"vpct-prod-cos-vpe-z1","auto_delete":true}' \
  --new-reserved-ip '{"subnet":{"name":"vpct-prod-app-z2"},"name":"vpct-prod-cos-vpe-z2","auto_delete":true}' \
  --new-reserved-ip '{"subnet":{"name":"vpct-prod-app-z3"},"name":"vpct-prod-cos-vpe-z3","auto_delete":true}' \
  --resource-group-name vpct-lab
ibmcloud cbr zone-create --name vpct-prod-vpc-zone --description "requests from vpct-prod" --vpc $VPC
ibmcloud cbr rule-create --description "vpct-cos-vpc-only" --service-name cloud-object-storage \
  --service-instance $COS_GUID --zone-id $ZONE --enforcement-mode report
ibmcloud cbr rule-patch $COS_RULE --enforcement-mode enabled
Step 2 · Run it

Reach it from inside, then enforce the lock

First a server in the VPC uses the gateway. Then the rule is switched from report-only to enabled, and the same request is made from a laptop outside the VPC. Run each command in turn.

bash

# on a vpct-prod server

dig +short s3.direct.us.cloud-object-storage.appdomain.cloud
10.20.1.24

The name resolves to a private address in the app subnet, one of the gateway's reserved IPs.

nc -zv -w 5 s3.direct.us.cloud-object-storage.appdomain.cloud 443
Connection to s3.direct.us.cloud-object-storage.appdomain.cloud (10.20.1.24) 443 port [tcp/https] succeeded!
ibmcloud is security-group-rule-delete vpct-prod-vpe-sg <rule-id> -f
Deleting rule r014-1414…4045 from security group  vpct-prod-vpe-sg
OK
Rule r014-1414…4045 is deleted.

The only rule that allows port 443 has been deleted.

The same nc command runs again. What happens?

Show the answer

It times out. The gateway's security group is what allows the connection, and you can run the command to see that.

nc -zv -w 5 s3.direct.us.cloud-object-storage.appdomain.cloud 443
nc exit 1
nc: connect to s3.direct.us.cloud-object-storage.appdomain.cloud (10.20.1.24) port 443 (tcp) timed out: Operation now in progress

Adding the rule back made it succeed again.

# from a laptop outside the VPC, with the rule in report-only mode

ibmcloud cos buckets --ibm-service-instance-id $COS_GUID
1 bucket found in your account:

Name                  Date Created (UTC)
vpct-backups-nrt29b   Oct 30, 2026 at 18:03:54

Report-only allows everything and logs what a rule would deny.

ibmcloud cbr rule-patch $COS_RULE --enforcement-mode enabled
OK
description           vpct-cos-vpc-only
enforcement_mode      enabled

Now the laptop repeats the bucket list. What happens?

Show the answer

The request is denied. A context-based restriction applies in addition to IAM. The laptop's IAM access is fine, but its request doesn't come from the VPC.

# from the laptop, rule enabled

ibmcloud cos buckets --ibm-service-instance-id $COS_GUID
FAILED
Access to the IBM Cloud account was denied — please verify that the Service Instance ID / CRN is valid, and ensure the correct endpoint URL is being used (check using ‘ibmcloud cos config list’).

The message doesn't say that a restriction caused it.

# on a vpct-prod server, through the gateway; the token goes in on standard input

curl -s -o /dev/null -w "%{http_code}\n" -H @- https://s3.direct.us.cloud-object-storage.appdomain.cloud/vpct-backups-nrt29b
200

From inside the VPC the answer is 200.

# the same request from the laptop, for comparison
403

From outside the VPC the answer is 403.

Step 3 · Design it

How does a VPC reach a service in another VPC?

This compares Private Path with the other ways. Northgate's shared-services team runs a web service in one VPC, and the prod VPC needs to use it.

The two VPCs have no route between them. The provider wants to approve each consumer before it connects. Which option?

Show the answer

Private Path. The provider creates the service and gives consumers its CRN. The consumer creates an endpoint gateway with that CRN, which sends a connection request. The provider permits or denies it. Traffic stays on IBM's backbone.

Two VPCs trust each other, and whole networks in each should reach the other. Which option?

Show the answer

Transit Gateway. It's for VPCs that trust each other, because it joins whole networks by routes. Module 6 covers it.

The consumer has created its endpoint gateway. The provider lists the connection requests.

$ ibmcloud is private-path-service-gateway-endpoint-gateway-bindings vpct-shared-pps
ID               Account ID    Status    Lifecycle state
r014-edb3…5eaa   <redacted>    pending   stable

The binding shows pending. Can the consumer reach the service?

Show the answer

No. The service's default access policy was review, which leaves each request for the provider to approve. After the provider permitted it, the status read permitted. The consumer then bound a reserved IP to the gateway, and a request to that address returned the page from the provider's server, although the two VPCs have no route between them.

Step 4 · Spot the fault

An enforced rule blocks an encrypted volume create

Northgate has enforced a rule on its Key Protect instance, so only the VPC can reach it. Northgate's admin, working inside the VPC, then tries to create an encrypted volume with a key from that instance.

$ ibmcloud is volume-create vpct-cbr-test-vol general-purpose us-east-1 --capacity 10 --encryption-key $KEY_CRN --resource-group-name vpct-lab
Creating volume vpct-cbr-test-vol in resource group vpct-lab
FAILED
Failed to create volume.

FAILED
Error code: volume_encryption_key_not_authorized
Error message: You are not authorized to access the provided volume encryption key.

The admin has IAM access to the key. What blocks the volume?

Show the answer

The enforced rule on Key Protect. With the rule set back to report-only, the same command succeeded, so the rule is what blocks it. The request to Key Protect comes from VPC block storage, not from the admin's server.

How do you keep the rule and still allow the volume create?

Show the answer

Add a zone for server-protect. VPC block storage reaches Key Protect as that service. With that zone as a second context, the volume create succeeded and a request from the laptop was still denied. Two contexts mean a request is allowed if it matches either. A zone for the service named is didn't help.

Right after you enforce the Key Protect rule, the same request from your laptop sometimes succeeds. Is the rule broken?

Show the answer

No. During that time the same request sometimes succeeds and sometimes fails. Wait until it fails every time before you trust a denial. The Object Storage rule was denied at once.

Step 5 · Check yourself

Four questions

Review question from Unit 5.2. A server resolves app.vpct.internal to an address, but curl to it times out. The two VPCs have no route between them. What is missing?

Show the answer

A route between the VPCs. Name resolution and reachability are separate. Both VPCs resolved the name, and the connection still timed out because no route joined them.

What does a context-based restriction look at that an IAM policy does not?

Show the answer

Where the request comes from. A restriction limits access by where a request comes from, on top of IAM. An IAM policy limits access by who is asking and doesn't look at the network.

A server reaches Object Storage through the public gateway. The restriction's zone holds only the VPC. Is the request allowed?

Show the answer

No. IBM says that to allow access from a VPC to public endpoints, you add the public gateway addresses to the zone as well. The lab's zone has none, so requests that leave through the public gateway don't match.

In a shared account you write a rule for the whole Object Storage service, not one instance. What is the risk?

Show the answer

It denies other teams' requests too. Every rule in our lab names one service instance and never a whole service, to avoid this.
