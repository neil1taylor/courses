Encryption with Key Protect

By the end of this unit you'll know what makes a volume encrypted with a key you own, how to read the two values of the Encryption line, and how to choose between IBM-managed and customer-managed encryption.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier. Its auditor, who checks Northgate's security controls, wants to know who holds the key to the disks on the new app servers. The commands and output are real, even though the company is made up.

Every command and line of output here comes from a real run. Account and key IDs are shortened.

Step 1 · Explore the parts

Four things make an encrypted volume

A volume encrypted with a key you own needs four things: a Key Protect instance, a root key, a rule that lets Block Storage use the key, and a volume created with the key. Select a part of the drawing to see what it does and which line makes it, or click a line. We left out the options that only name the lab's tags.

↑ tap any box

Key Protect instance

Key Protect is IBM Cloud's key management service. It stores root keys. The standard plan is a multi-tenant service with FIPS 140-2 Level 3; the dedicated one is single-tenant with FIPS 140-3 Level 4.

Root key

A key you own, held in Key Protect. IBM wraps each volume's passphrase with it.

Watch for this. The ibmcloud kp commands go to the region stored in the plug-in's own configuration, even if you targeted a different region. Run region-set first.

The rule

A service-to-service authorization: an IAM rule that lets Block Storage (server-protect) use Key Protect (kms) with the Reader role. Here it is scoped to this one instance.

Watch for this. IBM's own command leaves out the instance ID, so the rule covers every Key Protect instance in the account. The lab scopes the rule to one instance, so the rule is yours and no other team's rule makes it work.

The volume

The volume is created with the key's CRN. Its Encryption line then reads user_managed. A volume with no key reads provider_managed.

ibmcloud resource service-instance-create vpct-key-protect kms tiered-pricing us-east -g vpct-lab
ibmcloud kp region-set us-east
ibmcloud kp key create vpct-volume-root-key -i $KP_ID
ibmcloud iam authorization-policy-create server-protect kms Reader --target-service-instance-id $KP_ID
ibmcloud is volume-create vpct-prod-app-z1-02-data1 general-purpose us-east-1 --capacity 10 \
  --encryption-key $KEY_CRN

Step 3 · Spot the fault

Two messages that look like failures

A Northgate admin creates an authorization rule, in this case the one that lets file shares replicate between regions. The account already holds a rule like it, and the command returns this:

FAILED
Error response from server. Status code: 409; description: {"trace":"…","status_code":409,"errors":[{"code":"policy_conflict_error","message":"The policy wasn't created because an access policy with identical attributes already exists. ...

What should the admin do?

Show the answer

Nothing. Test runs showed that if the account already holds a rule with the same attributes, the command fails with policy_conflict_error (status 409) and names the existing rule. That rule does the work, so you need no new one.

The CLI is logged in and targeted at us-east. ibmcloud kp key create fails with Unauthorized, although the Key Protect instance is in us-east.

What caused it?

Show the answer

The plug-in used its own stored region. The kp commands go to the region in the plug-in's own configuration, even if you targeted a different region. Without ibmcloud kp region-set us-east the plug-in used eu-de, and the create failed with Unauthorized.

Step 4 · Design it

Whose key should Northgate use?

Northgate has four situations to decide. Pick an answer for each, then read the worked answer.

Northgate has no requirement to own the keys. What should it do?

Show the worked answer

Do nothing. IBM-managed encryption is the default, with nothing to set up. IBM holds the keys. Boot volumes, data volumes and file shares have it.

The auditor says Northgate must own and rotate the key. What should it use?

Show the worked answer

Customer-managed, with Key Protect standard. Standard is what the lab chose. It's a multi-tenant service with FIPS 140-2 Level 3. The single-tenant key service is Key Protect dedicated, with FIPS 140-3 Level 4.

Northgate already holds an instance of Hyper Protect Crypto Services. What should it do?

Show the worked answer

Plan to migrate. Hyper Protect Crypto Services is deprecated. Existing instances work only until the end date in IBM's deprecation notice, and IBM advises you to migrate keys to a dedicated Key Protect instance.

A file share was created with IBM-managed keys. Later the auditor wants a customer root key on it. What can Northgate do?

Show the worked answer

It can't be changed. A customer root key can replace IBM-managed keys when the share is created, but the choice can't change afterwards.

Step 5 · Check yourself

Four questions

Why does the lab scope the rule with --target-service-instance-id?

Show the answer

So the rule is yours. The lab account is shared and another team may already have a rule. IBM's own command leaves out the instance ID, so it covers every Key Protect instance in the account.

You delete a Key Protect instance that holds no keys. Is it gone at once?

Show the answer

No, it's scheduled for deletion. ibmcloud resource reclamations lists it with the state SCHEDULED. Key Protect bills while the instance exists and holds no keys.

How long must you keep the key and the rule?

Show the answer

For as long as the volume exists. With the rule and the key in place, Block Storage can open the volume when it attaches. IBM lists disabling, rotating and deleting keys as things to plan for. The lab didn't disable or delete the key, so we didn't test what happens then.

Review from unit 4.1. A data volume is 20 GB. Can you make it 10 GB with volume-update?

Show the answer

No, capacity can only grow. IBM says the capacity of a tiered volume can only grow, and only while it is attached to a running server.
