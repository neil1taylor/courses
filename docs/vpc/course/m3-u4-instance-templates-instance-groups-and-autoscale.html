Unit 4 of Module 3

Instance templates, instance groups and autoscale

By the end of this unit you'll be able to read an instance template, say what a group does with it, and predict how an autoscale group grows.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier that is moving off vSphere, though the commands and output are real. Its web tier needs to grow when it's busy and replace a server that fails, without anyone typing a create command each time.

Every command and line of output in this unit comes from real runs in a test account.

Step 1 · Explore the parts

One template, many servers

A template records everything you passed to instance-create, so one object can make many servers. Select a part to see what it holds, or click a line.

↑ tap any box

Where

A template is a saved set of server settings: zone, profile, image, subnet, keys, volumes, network interface and user data. This one names the VPC, resource group, zone and profile.

From vSphere: a VM template maps to an image and an instance template. It's a rough mapping, because in VPC the image holds the disk and the template holds the settings.

Watch for this. The template names one zone, but the group in step 2 is given three subnets, and its members landed in us-east-1, us-east-2 and us-east-3.

What it runs

The image and the SSH keys. The template here uses the custom image vpct-prod-web-image-v2. The user data is also stored in the template, but this command doesn't print it.

Watch for this. The template names no floating IP, because IBM's instance groups don't accept one.

Boot volume

The template names the boot volume and its tags.

Watch for this. A volume name must be unique, so a second server made by hand from this template fails with Volume with name "vpct-prod-web-tpl-boot-vol" already exists unless you give it its own name.

Network

The primary network attachment, the subnet and the name of the reserved IP.

Watch for this. These names must also be unique in the VPC. A group adds two random strings to each name when it builds a member, and a template with no names gets four random words for them.

Watch for this. An instance template takes no tags either, and tag-attach fails with The specified resource type is not supported: project.

The group keeps between 1 and 3 servers, with a target of 50% average CPU.

IBM's limits are 90 to 600 seconds for the window, 120 to 3600 seconds for the cooldown, and one policy for each metric type.

Before you run the next command, suppose the group's only member runs the first template and Northgate switches the group to a second template whose servers burn CPU. Does the existing member change?

Show the answer

No. IBM doesn't say whether existing members change. In the recorded run they didn't: the first member kept the old template, its CPU stayed low and the manager added nothing. Deleting that member made the group replace it from the load template.

Step 3 · Predict

Pick an answer, then see what really happened

The settings are a minimum of 1, a maximum of 3, an aggregation window of 90 seconds, a cooldown of 300 seconds and a CPU target of 50%. The group's one member runs a loop that keeps the CPU busy.

When did the recorded group first show two members?

Show the answerIt took about four and a half minutes.

Between 234 and 267 seconds. The readings showed one member up to 234 seconds and two at 267 seconds. Trimmed from the lab recording:

When did it show three members?

Show the answerThe group stopped at three members.

At about 10 and a half minutes. It showed three members at 632 seconds, then stopped at the maximum of three, and the cooldown holds further changes for 300 seconds after each change.

Step 4 · Spot the fault

A pool the group manages

The error was copied from a run where an instance group is attached to a load balancer pool.

$ ibmcloud is load-balancer-pool-member-delete vpct-prod-web-alb vpct-prod-web-pool <member-id> --vpc vpct-prod -f
FAILED
Error code: member_managed_pool_create_conflict
Error message: Member can not be created. Pool is managed by instance group 'r014-…-d2ab'.

Northgate tries to remove a server from the pool by hand and gets this error. Why?

Show the answerThe group manages the pool, so you can't.

The pool is managed by an instance group. Once a group is attached to a pool, you can no longer add, delete or update the pool's members, though you can still update the pool. To replace a member, delete its group membership, which deletes its server, and the group builds a replacement.

The group built a replacement after Northgate deleted a membership. What does Northgate need to do about it?

Show the answer

Name and tag it. The replacement comes back with generated names for the server, boot volume, network attachment, virtual network interface, reserved IP and membership, and its boot volume has no tags. Run the naming and tagging loop again after a replacement.

Step 5 · Check yourself

Three questions

Review from unit 3.3. Two servers are in a placement group. You delete the group while they still run. What happens?

Show the answer

It fails. IBM says you can't delete a group that has servers. The error is placement_group_in_use: placement group is referenced by one or more instances.

IBM's example: four servers at 80%, 70%, 65% and 85% CPU, with a target of 70%. How many servers should the group have?

Show the answer

5. The manager adds up the average CPU of every server, which comes to 300%. Divided by the target of 70% that is 4.29, which rounds up to 5, so the group adds one server.

Northgate wants exactly three web servers, always, with failed ones replaced, and the load doesn't change. Which group?

Show the answer

A static group. It suits a fixed number of servers that the group repairs, while an autoscale group suits load that changes. Servers made by hand have no automatic repair. Keep in mind that an instance group doesn't accept a template with a secondary network interface, or with a primary IP address or floating IP on the primary interface.
