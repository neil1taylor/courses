Unit 1 of Module 6

Ways to connect VPCs and sites

By the end you can pick a way to join VPCs, regions and sites, and say what a Transit Gateway, a VPN and a prefix filter do not do.

About 10 minutesNo account needed5 steps

Northgate Freight is a made-up haulier. Its servers now sit in several VPCs and it still has a data centre. This module joins them and protects what passes between them.

Every command and line of output in this unit comes from a real run, recorded in tutorial chapters 71, 73, 74 and 77. The choices come from chapter 79, which cites IBM's pages. The review question repeats one from unit 2.2.

Step 1 · Design it

Pick a way for each need

Four needs. Pick an answer, then read the worked answer.

Prod, dev and shared services are VPCs in one region. They must reach each other.

Show the worked answer

A local Transit Gateway joins VPCs in one region and needs no tunnel. A gateway takes 10 VPC connections, and a VPC can join many local gateways.

From NSX: an NSX Tier-0 or Tier-1 router maps roughly to a route table and a Transit Gateway.

Northgate adds a recovery region. The two hub VPCs, in different regions, must reach each other.

Show the worked answer

A global Transit Gateway joins VPCs in several regions. A VPC joins only one global gateway, and many local ones.

The data centre must reach the VPCs over the internet, and only a few prefixes matter.

Show the worked answer

Static suits a few prefixes. A dynamic connection, with BGP, needs a Transit Gateway. A client-to-site VPN is for one person's device, and a GRE tunnel is for an appliance that runs its own tunnels.

The data centre needs a private link, not the internet.

Show the worked answer

Direct Link on Classic has had no new orders since 15 September 2025. "Transit Gateway Connect" is not an IBM product: there is no such page, command or type. The Direct Link row in chapter 79 is cited from IBM's pages, not built in the lab.

The gateway is attached. From a prod server, will nc -zv -w 3 to port 22 on the shared server and on the dev server work?

Show the answer

A gateway only joins networks. The prod subnet's network ACL allowed traffic only inside 10.20.0.0/16. Chapter 22 explains why each direction needs its own rule.

# on a vpct-prod server, before any network ACL change

nc -zv -w 3 $SHARED 22; nc -zv -w 3 $DEV 22

Step 3 · Spot the fault

The second global gateway

The hub VPC is already on the global gateway vpct-tgw-global. Someone creates a second global gateway and tries to connect the hub to it.

bash
ibmcloud tg connection-create <second-global-gateway-id> --name vpct-tgw-global2-hub --network-type vpc --network-id <crn of vpct-hub>
FAILED
Error code: invalid_state
Error message: The requested network is already connected to an existing transit gateway.

What does the error tell you?

Show the answer

The hub is on vpct-tgw-global. A VPC joins one global gateway and many local ones, so in this design the prod, dev and shared VPCs stay on the local gateway. Chapter 77 says to delete the second gateway once you have seen the error.

Step 4 · Predict

A prefix filter on the dev connection

The lab added a filter to the dev connection that denies 10.30.0.0/16 (with --le 32), then read a new route report.

From a prod server, what happens when you connect to the dev server and to the shared server on port 22?

Show the answer
nc: connect to 10.30.0.4 port 22 (tcp) timed out: Operation now in progress
Connection to 10.40.0.12 22 port [tcp/ssh] succeeded!

The dev prefix was missing from the new route report. A route a filter drops is not shown with a status. It is gone.

Does that filter keep dev away from prod only?

Show the answer

A filter on one connection decides which of its prefixes every other connection can reach. IBM's page says so, and a reader may expect a filter between two VPCs. The lab tested only prod to dev, because the dev server had no public address.

Step 5 · Check yourself

Three questions

A VPN tunnel shows up but nothing passes. Where do you look first?

Show the answer

The connection is up when one tunnel is up. In the lab the second tunnel stayed down on both sides and traffic passed. Before the network ACL rules existed, a connection from the site timed out although the tunnel was up. A new security group also allows nothing outbound.

Which of these joins names, not packets?

Show the answer

DNS sharing lets many VPCs use one hub's resolver. Private Path joins one service to a consumer.

Review question from Unit 2.2. A network ACL allows outbound traffic from a web subnet to port 443. Why does the web server still get no answer until you add an inbound rule too?

Show the answer

The web ACL needs reply rules because the ACL checks each packet by itself. Rules run in order, top to bottom. A security group is the stateful one.
