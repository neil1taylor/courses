Block or file?

Step 1 · Explore the parts

A disk of its own, and a folder to share

Four parts, in the commands that create them. Select a part of the drawing to see what it does and which lines make it. You can also click a line. The resource group and tag options are left out.

↑ tap any box

Data volume

A block volume is a disk that attaches to one server. A data volume is one attached in addition to the boot volume. general-purpose gives 3 IOPS per GB; the 10 GB volume shows 3000 IOPS.

From vSphere: roughly a VMDK on a datastore. This is a rough mapping, not an IBM statement.

Watch for this. The sdp profile is for allowlisted accounts only. Check with ibmcloud is volume-profiles before you design around it.

Attachment

The link between a volume and a server. It has its own name and an auto-delete setting. With auto-delete true, deleting the server deletes the volume.

Watch for this. The volume and the server must be in the same zone.

File share

A shared folder reached over NFS by many servers at once. The zonal profile is dp2, from 10 GB. Servers mount it over NFS version 4.1 or higher.

From vSphere: roughly the other half of a datastore: a folder for many hosts, where a volume is a disk for one.

Watch for this. Windows is not supported. You cannot change a share's profile after creation.

Mount target

The network endpoint through which servers mount the share. It needs a network interface and a security group.

Watch for this. The security group must allow inbound NFS over TCP from the servers that mount the share. The chapter used port 2049.

ibmcloud is volume-create vpct-prod-app-z1-01-data1 general-purpose us-east-1 --capacity 10
ibmcloud is instance-volume-attachment-add vpct-prod-app-z1-01-data1-att vpct-prod-app-z1-01 vpct-prod-app-z1-01-data1 --auto-delete true
ibmcloud is share-create --profile dp2 --zone us-east-1 --size 10 --iops 100 --name vpct-prod-app-share --initial-owner-uid 1000 --initial-owner-gid 1000
ibmcloud is share-mount-target-create vpct-prod-app-share --name vpct-prod-app-share-mt1 \
  --transit-encryption none --access-protocol nfs4 \
  --vni-name vpct-prod-app-share-mt1-vni0 --vni-auto-delete true \
  --subnet vpct-prod-app-z1 --vni-sgs vpct-prod-fs-sg --vpc vpct-prod

Step 3 · Design it

Disk, folder or object store?

Three Northgate needs. Pick a choice, then read the worked answer from chapter 40.

Each app server needs its own data disk.

Show the worked answer

The series uses a general-purpose volume. The sdp profile needs an allowlisted account. A block volume is one server's own disk.

Both app servers must read and write the same folder.

Show the worked answer

A block volume is not shared. A zonal dp2 share is mounted over NFS by many servers, and it can have a replica in another zone or region.

Backups and logs must be kept outside the VPC.

Show the worked answer

Chapter 40's table sends backups and logs outside the VPC to Object Storage. Objects are reached over HTTP, not files over NFS.

Step 4 · Predict, then spot the fault

Two things that catch people out

Northgate raises the data volume from 10 GB to 20 GB with volume-update --capacity 20 while the server runs. What is left to do inside the server?

Show the answerTwo steps, not one.

The chapter ran sudo resize2fs /dev/vdd and then df -h /data showed 20G. The file written before was still there. IBM says capacity of a tiered volume can only grow, and only while it is attached to a running server.

A Northgate admin mounts the share on an Ubuntu 26.04 server with no extra options:

sudo mount -t nfs4 <mount-path> /mnt/share

The mount succeeds. Every write fails with Permission denied.

What is missing?

Show the answer

Without it the client mounted with sec=null, and every write failed. The chapter used sudo mount -t nfs4 -o sec=sys <mount-path> /mnt/share.
